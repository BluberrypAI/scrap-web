# 완료 가능 산출물의 다음 행동 선택

> 이전 검증 기록이다. 현재 UI는 별도 완료/다음 업체 버튼을 제거하고 처리 결과에서 완료·추가 가공·보관 중을 함께 고른다. 최신 동작·검증은 [처리 결과 통합 등록](output-disposition-card-sync-20261120.md)을 따른다.

2026-11-20 사용자 요청: B가 완료 가능한 산출물을 기록한 뒤에도 완료 또는 다음 업체 인계를 선택한다. PET 플레이크 종료와 C에서 PET 펠릿까지 처리하는 두 경우를 실제 로컬 웹에서 검증한다.

## 동작

- 현재 보유 기업의 처리 결과가 서버 `terminal_states`에 해당하면 `여기서 처리 완료`와 `다음 업체로 보내기`를 표시한다. 첫 진입에서 한쪽을 자동 선택하지 않는다.
- 완료를 고르면 기존 완료 근거·용도·확인 절차를 사용한다. 다음 업체를 고르면 현재 산출물 기준의 사진·AI 후보 검토·도로거리·인수 요청을 그대로 사용한다.
- 인수 요청 전까지 선택을 바꿀 수 있다. 이미 진행한 업체 검토가 있는 경우 새로고침 뒤에도 검토 결과를 다시 볼 수 있다.
- 다음 업체가 없거나 검토가 실패해도 자동 완료하지 않는다. 인수 요청 중·운송 중·입고 처리 중·불일치 보류·완료 건에는 이 선택을 노출하지 않는다.
- 서버의 완료 허용 상태·입고 QR·산출물 불일치 보류·revision 규칙과 문진 엔진은 변경하지 않는다. API·DB 스키마 변경 없음.

## 검증

- [x] 웹 106개 검사와 Vite·Docker 빌드 통과
- [x] PET 플레이크에서 B가 완료 선택·입력·완료하고 A에서도 확인
- [x] 다른 물량의 B가 다음 업체 선택·AI 검토·C 요청·수락·운송·QR 입고, C 펠릿 기록·완료 후 A 전체 이력 확인
- [x] 검토 중 선택 버튼 잠금, 완료 후 조작 숨김을 웹에서 확인. 비관리·불일치 보류 상태는 렌더 회귀 검사로 확인

사업장 이름·공정 근거는 공개 업체 자료를 쓰되 테스트 계정 연결·물량·성상·완료 기록은 합성이다. 실제 업체 연락·운영 배포는 하지 않는다.

새 문진 두 건을 실제 문진 API로 판정·확정했다. 두 건의 **A→B 검토·수락·운송·QR 입고는 실제 API로 준비**했다. **B의 산출물 입력·완료/다음 업체 선택부터는 실제 웹 브라우저로 수행**했다. 둘째 건의 C 수락·B 운송/QR 발급·C QR 링크 입고·펠릿 입력·완료 및 A의 두 결과 조회도 웹에서 수행했다. 가입부터 전부 웹으로 시험했다는 뜻은 아니다.

B→C 검토는 실제 Azure 호출로 5개 업체를 반환했으며 공개 근거 3건을 재사용하고 공개 근거 2호출·물량 5호출을 수행했다(약 29.36초). 후보의 출발점은 B 사업장이며 디와이폴리머 평택까지 카카오 자동차 도로거리 37.350km를 확인했다. A→B 구간 11.229km와 별개다. 실제 차량 GPS·화물차 전용 경로를 뜻하지 않는다.

첫 건은 요청 전 완료/후속 인계를 전환해 보았고, 둘째 건은 검토 중 새로고침 뒤에도 후속 업체 선택·검토가 유지되는지 확인했다. C에서 펠릿 기록 후에는 이전 B의 선택을 물려받지 않고 다시 선택하도록 표시했다. 완료는 명시적인 확인 입력 이후에만 저장됐다. A가 조회한 둘째 건에는 QR 입고 2건·산출물 2건이 있었다.
