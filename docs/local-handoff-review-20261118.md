# 신규 기업 두 계정으로 확인한 로컬 인계 화면

2026-11-18, `localhost:5178` 통합 Docker에서 Edge 일반 창(A)과 InPrivate 창(B)을 사용했다. 운영 배포·푸시는 하지 않았다.

## 시나리오와 확인 범위

- A: 엔피씨 주식회사 화성공장, B: 독산 화성. 회사명·사업장 공개 정보를 사용했으며 가입 계정·시설 계정 연결·물량·체크 선언은 로컬 합성 시험이다. 실제 업체 인증·허가 확인·수락을 뜻하지 않는다.
- 개발용 로그인으로 두 기업을 새로 등록했다. 소셜 OAuth 가입 자체는 이번 검증에 포함하지 않았다.
- A의 새 PP 문진이 `51-03-01`로 연결됐다. 현재 형태는 파쇄품, 시험 물량은 1,000kg. 실제 기업 물량이 아닌 공개 예시 사진임을 상태 설명에 적었다.
- 실제 Azure 검토에서 독산의 PP 분쇄품 투입·펠렛 생산 공개 근거가 확인됐다. 사진은 작은 여러 색 조각을 관찰했지만 예시 사진으로 이번 물량의 오염·순도를 입증할 수 없다고 명시했다. 순도·수분·현재 허가·이번 반입 승인은 미확인으로 남았다.
- 독산 후보의 A 출발 도로거리는 OSRM 자동차 경로 6.4km로 표시됐다.
- A 요청, B 받은 물량 카드·사진 조회, B 시험 수락, A 운송 시작, QR 발급, B QR 입고 및 담당 기업 변경을 두 창에서 확인했다.

## 발견해서 수정한 화면 문제

1. 가입 업종에 플라스틱 제품 제조·폐기물 재활용, 설비에 선별·파쇄·압출 선택을 추가했다.
2. 주소 검색이 국내 상세 주소를 찾지 못할 때 확인한 좌표를 직접 지정할 수 있게 했다. 입력한 좌표는 한국 범위를 검사한다.
3. 업체 수락과 실제 출발이 구분되지 않아 `운송 시작`을 추가했다. QR 발급 자체는 출발로 취급하지 않는다.
4. 인계 기록이 최신 점 하나만 보라색이던 문제를 고쳤다. 기록된 모든 점·연결선에 보라색 체크를 유지하고 최신 건에만 `최근 단계`를 붙인다. 상단 진행 표시의 완료 단계도 보라색으로 유지한다.
5. 다른 기업이 입고해도 열린 상세 화면은 갱신되지 않았다. 5초 주기·창 복귀 때 조회하고, 작업 중 조회 및 늦게 온 이전 응답을 차단한다. 내용이 같으면 화면을 다시 그리지 않는다.
6. 최종 펠렛 산출물을 기록한 뒤에도 사진·다음 업체 검토가 다시 표시됐다. 서버가 정한 완료 가능 산출물이면 완료 근거·용도·확인만 표시한다. 중간 파쇄품이면 다음 인계용 검토를 유지한다. 두 경우를 렌더 테스트로 구분했다.

웹 89개 테스트 통과, Docker 웹 빌드 통과. 자동 갱신은 SSE/WebSocket이 아닌 주기 조회이며 숨겨진 탭에서는 멈춘다. 같은 날 후속 요청으로 카카오 지도·주소 검색·길찾기를 연결했고, 인계 지도도 도로 좌표를 사용하도록 전환했다. 실제 A→B 경로 6.495km·164좌표와 주소 검색 결과 핀·서버 저장, 순환자원지도 표시를 웹에서 확인했다.
