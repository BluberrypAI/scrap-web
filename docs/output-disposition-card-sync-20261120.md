# 처리 결과 통합 등록과 카드 자동 갱신

2026-11-20 사용자 지시로 이전 별도 완료/다음 업체 선택 UI를 대체한다.

- 산출물 형태·중량·상태·근거 입력 안에 `다음 진행: 완료 / 추가 가공 / 보관 중`을 필수 선택한다. 완료 시 같은 근거를 재사용하고 용도·확인만 추가한다. 결과 등록 한 번으로 완료하며 별도 종료 버튼은 없다.
- 추가 가공은 현재 산출물로 업체를 검토한다. 보관 중은 업체 검토를 표시하지 않고, 기록된 결과 카드의 다음 진행을 바꾸면 같은 산출물로 재개한다. 산출물/공정은 중복 추가하지 않는다.
- 완료 불가 상태의 완료 선택은 비활성화하며 서버도 검증한다. 타 기업·불일치 보류·운송 중·완료 건의 변경을 막는다.
- A 목록은 5초 주기 및 창 복귀 시 조회한다. 조회가 겹치지 않으며 오류 시 이전 카드를 보존하고 회복한다. 카드 펼침 상태를 유지하면서 B·C 사업장을 최신 공정 기록/실제 인계 건으로 그린다. 완료 건의 완료 이력 이동은 유지한다.

## API 의존

scrap-server의 `output-disposition-card-sync` 명세를 먼저 적용해야 한다. `/output`의 `next_action`, `completion_reference`, `intended_use`, `completion_confirmed` 추가 필드와 `/output-action`을 사용한다. `stored` 문자열 상태를 보관 중으로 표시한다. 기존 `/finish` API는 호환을 위해 서버에 남지만 웹은 호출하지 않는다.

## 검사

웹 108개 검사·Docker/Vite 빌드 통과. 서버 693개 검사 통과. 독립 브라우저 연결이 없는 환경에서 A 카드 자동 갱신 검사는 **A를 연 채 별도 HTTP 세션의 실제 B→C 인수 요청 API**로 신호를 발생시킨다. B/C 결과 입력·수락·QR·완료는 브라우저로 확인한다. A→B 입고까지는 실제 API로 시험 데이터를 준비한다. 물량·계정 연결·성상은 합성이며 실제 업체 연락·운영 배포는 하지 않는다.

| 시나리오 | 확인한 결과 |
| --- | --- |
| A→B 종료 | PET병100kg → B 플레이크90kg. 결과 등록에서 완료 선택·용도·확인 후 한 번에 완료. A에서도 완료 확인 |
